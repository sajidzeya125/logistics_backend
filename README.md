# Real-time Logistics API

A FastAPI backend for managing users, drivers, delivery locations, orders, routes, and delivery progress. The API uses PostgreSQL for persistence, SQLAlchemy for database access, Alembic for migrations, and JWT bearer tokens for authentication.

## Features

- User registration, profiles, and authentication
- Driver profiles and availability tracking
- Delivery location management and nearby-location search
- Orders with line items and status tracking
- Route creation, status management, and route optimization
- Delivery stop progress and delivery history
- Interactive OpenAPI documentation
- Database migrations with Alembic

## Tech Stack

- Python
- FastAPI
- PostgreSQL
- SQLAlchemy
- Alembic
- Pydantic Settings
- JWT authentication
- GeoAlchemy2

## Requirements

- Python 3.10+
- PostgreSQL 13+
- A virtual environment is recommended

## Installation

```bash
git clone https://github.com/sajidzeya125/logistics_backend.git
cd logistics_backend

python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

On Windows PowerShell, activate the environment with:

```powershell
.\.venv\Scripts\Activate.ps1
```

## Configuration

Create a `.env` file in the project root. Do not commit this file or real credentials.

```env
DATABASE_HOSTNAME=localhost
DATABASE_PORT=5432
DATABASE_NAME=logistics
DATABASE_USERNAME=postgres
DATABASE_PASSWORD=your-password
SECRET_KEY=replace-with-a-long-random-secret
ALGORITHM=HS256
ACCESS_TOKEN_EXPIRE_MINUTES=30
```

Create the PostgreSQL database before running migrations:

```bash
createdb logistics
```

If your PostgreSQL setup requires a PostGIS-enabled database, enable the extension before applying migrations:

```sql
CREATE EXTENSION IF NOT EXISTS postgis;
```

## Database Migrations

Apply the existing migrations:

```bash
alembic upgrade head
```

After changing SQLAlchemy models, generate and review a migration:

```bash
alembic revision --autogenerate -m "describe the schema change"
alembic upgrade head
```

## Running the API

Start the development server from the repository root:

```bash
uvicorn app.main:app --reload
```

The API is available at [http://127.0.0.1:8000](http://127.0.0.1:8000).

Interactive documentation:

- Swagger UI: [http://127.0.0.1:8000/docs](http://127.0.0.1:8000/docs)
- ReDoc: [http://127.0.0.1:8000/redoc](http://127.0.0.1:8000/redoc)
- OpenAPI schema: [http://127.0.0.1:8000/openapi.json](http://127.0.0.1:8000/openapi.json)

Health check:

```bash
curl http://127.0.0.1:8000/health
```

Expected response:

```json
{"status": "ok"}
```

## API Overview

| Area | Base paths | Description |
| --- | --- | --- |
| Authentication | `/login`, `/logout`, `/refresh`, `/verify` | Obtain and verify access tokens |
| Users and drivers | `/users` | Manage users, driver profiles, and availability |
| Locations | `/locations` | Manage locations and search nearby locations |
| Orders | `/orders` | Create orders, manage items, and update statuses |
| Routes | `/routes` | Create, optimize, and manage delivery routes |
| Deliveries | `/deliveries` | Track route stops and delivery history |

Most endpoints require a bearer token. Authenticate through `/login`, then send the returned token with requests:

```http
Authorization: Bearer <access-token>
```

## Development

Run the application with reload enabled during development:

```bash
uvicorn app.main:app --reload
```

Keep database credentials and JWT secrets in environment variables. Review autogenerated Alembic migrations before applying them to shared or production databases.
